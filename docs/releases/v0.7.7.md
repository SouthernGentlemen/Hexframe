# Hexframe v0.7.7

**Product:** Hexframe

**Commit:** the commit this tag names — `git rev-list -n1 v0.7.7`

## Scope

Make Hexframe's supported-device boundary explicit and enforce it before unsupported visitors
reach training. Coarse-pointer devices and viewports through 960px now receive a dedicated
desktop-only screen instead of the project overview or game runtime. The notice states that
mobile and tablet support is not planned while preserving source and case-study access.

## Included changes

- [HF-108] [FIX] Enforce the desktop-only support boundary
- [HF-109] [BUILD] Record and version the v0.7.7 desktop-support release

## Accessibility boundary

- The unsupported-device notice is exposed as a semantic note with a labelled heading.
- Coarse-pointer devices are gated at every width, and fine-pointer viewports through 960px are
  gated so the audited phone and tablet layouts cannot expose undersized navigation targets.
- Every link on the desktop-only screen has a target height of at least 44px.
- Fine-pointer desktop viewports above 960px retain the existing overview and training paths.
- A direct training-session URL cannot initialize the game while the gate applies.

## Known limitations

- Hexframe intentionally does not provide on-screen touch controls; mobile and tablet support is
  not planned.
- Desktop browsers in viewports at or below 960px receive the desktop-only notice and must widen
  the window to enter training.
